# grubby-gui — менеджер загрузки GRUB2

Графическая оболочка для `grubby`: управление записями загрузчика GRUB2 на
Fedora, RHEL 9+, AlmaLinux, Rocky, РЕД ОС, CentOS Stream и других
rpm-дистрибутивах.

**Технологии:** Python 3 + GTK 4 (PyGObject). Компилировать ничего не нужно.

## Возможности

| Действие | Что выполняется |
|---|---|
| Список записей меню с отметками «по умолчанию» и «загружено сейчас» | `grubby --info=ALL`, `--default-index` |
| Выбор ядра по умолчанию | `grubby --set-default-index=N` |
| Добавление и удаление параметров ядра (чипы, каталог из 27 популярных параметров с описаниями) | `grubby --update-kernel=<ядро>\|ALL --args=… --remove-args=…` |
| Применение ко всем записям, с выбором, трогать ли `/etc/default/grub` | `grubby --update-kernel=ALL [--no-etc-grub-update]` |
| Удаление записи из меню | `grubby --remove-kernel=<ядро>` |
| Добавление записи для своего ядра | `grubby --add-kernel … --initrd … --title … [--copy-default] [--make-default]` |
| **Переход на BLS** (если загрузчик работает не в режиме BLS) | `GRUB_ENABLE_BLSCFG=true` в `/etc/default/grub` + `grub2-mkconfig -o <grub.cfg>` |

- Перед применением показывается **точная команда**, её можно скопировать.
- Внизу есть **журнал** всех выполненных команд с кодами возврата и выводом
  (кнопка с терминалом в заголовке).
- До нажатия «Применить» ничего не меняется. Изменения подсвечены: зелёным
  отмечено добавляемое, красным зачёркнуто удаляемое.

## Переход на BLS

Если в `/etc/default/grub` не стоит `GRUB_ENABLE_BLSCFG=true` (так бывает,
например, на РЕД ОС), grubby меняет файлы в `/boot/loader/entries`, но GRUB
их не читает, и изменения не попадают в меню. В этом случае программа
показывает жёлтый баннер с кнопкой **«Перейти на BLS…»**. Тот же переход
доступен из меню ☰ → «Режим загрузчика (BLS)…».

Что происходит при переходе:

1. Создаются резервные копии `/etc/default/grub` и `grub.cfg` с суффиксом
   `.grubby-gui-<дата>.bak`.
2. В `/etc/default/grub` выставляется `GRUB_ENABLE_BLSCFG=true`: строка
   заменяется, а если её нет, дописывается. Остальное содержимое файла не
   трогается.
3. Выполняется `grub2-mkconfig -o <grub.cfg>`. Обычно это
   `/boot/grub2/grub.cfg`. На UEFI-системах, где полный конфиг лежит в ESP
   (`/boot/efi/EFI/<vendor>/grub.cfg`, а не заглушка), используется он.
   Точный путь показывается до подтверждения.
4. Если `grub2-mkconfig` завершился с ошибкой, оба файла восстанавливаются
   из резервных копий.

Если в `/boot/loader/entries` нет ни одной записи, переход заблокирован:
меню GRUB оказалось бы пустым. Программа подскажет, как создать запись
(`kernel-install add …`).

## Оформление окна в GNOME и KDE

- **GNOME** (и прочие окружения): кнопки находятся в заголовке окна (HeaderBar),
  рамку рисует GTK.
- **KDE Plasma, LXQt**: заголовок и рамку рисует оконный менеджер (Breeze),
  поэтому окно растягивается за края как обычно. Кнопки «Обновить»,
  «Добавить», журнал и меню переезжают на панель под заголовком.

Окружение определяется по `XDG_CURRENT_DESKTOP`. Принудительно выбрать режим
можно так: `GRUBBY_GUI_CSD=1 grubby-gui` (как в GNOME) или
`GRUBBY_GUI_CSD=0 grubby-gui` (рамка оконного менеджера).

## Безопасность и права

Сам интерфейс работает от **обычного пользователя**. При запуске через
`pkexec` поднимается маленький помощник `grubby-gui-helper`. Пароль
спрашивается один раз за сеанс, поэтому программа работает и под Wayland.

Помощник умеет только:
- запускать **grubby** с ключами из белого списка (без shell);
- читать состояние BLS;
- выполнять описанный выше переход на BLS.

Произвольные команды он не выполняет.

## Структура

| Файл | Назначение |
|---|---|
| `grubby_gui.py` | Интерфейс на GTK 4 |
| `grubby_core.py` | Основная логика без GTK: связь с помощником, разбор вывода grubby, сборка команд, каталог параметров |
| `grubby-gui-helper` | Привилегированный помощник (pkexec) |
| `data/` | .desktop, иконка, polkit-политика |
| `tests/` | Тесты и поддельные `grubby` и `grub2-mkconfig` для демо-режима |

## Установка

### Вариант 1. RPM (рекомендуется)

```bash
sudo dnf install rpm-build make
tar xzf grubby-gui-1.0.1.tar.gz && cd grubby-gui-1.0.1
make rpm
sudo dnf install ~/rpmbuild/RPMS/noarch/grubby-gui-1.0.1-1.*.noarch.rpm
```

### Вариант 2. Без установки, прямо из папки

```bash
sudo dnf install python3-gobject gtk4 grubby polkit
./grubby_gui.py
```

### Вариант 3. `make install`

```bash
sudo make install      # ставит в /usr; удаление: sudo make uninstall
```

## Попробовать безопасно (демо-режим)

```bash
make demo          # имитация grubby и grub2-mkconfig, система не меняется
make demo-reset    # вернуть демо в исходное состояние (режим не-BLS)
```

Состояние демо хранится в `~/.cache/grubby-gui-demo.json` и
`~/.cache/grubby-gui-demo-root/`.

## Требования

- **GTK 4.6+** и PyGObject: Fedora 35+, RHEL/Alma/Rocky 9+, РЕД ОС с GTK 4.
  На RHEL 8 GTK 4 нет, там используйте версию 1.0.0 на GTK 3.
- Python 3.6+
- grubby, grub2-tools (для перехода на BLS), polkit и графический агент polkit

## Тесты

```bash
make test               # логика и помощник, включая переход на BLS и откат
xvfb-run make gui-test  # GUI-сценарии в демо-режиме
```
